The embeddable widget is an IIFE bundle (`chat.js`) with a Shadow DOM launcher. Copy the exact snippet from the assistant **Install** tab.

**Zero-install (recommended):** load hosted `chat.js` from your ChatAI deployment — no npm package required.

**Programmatic embed:** install `@nightzeros/chatai-widget` or `@nightzeros/chatai-react` from npm when you need `mountWidget` / `<ChatWidget />` in your bundler (see [React](/docs/react)). The hosted IIFE is not published to npm.

Browser baseline: modern evergreen browsers with Shadow DOM and `fetch` / streaming support.

## Hosted script (recommended)

Load `chat.js` from your ChatAI origin. Production hosted URL:

```html
<script
  src="https://app.nightzeros.com/widget/chat.js"
  data-assistant-id="asst_your_public_id"
  async
></script>
```

Self-hosted ChatAI instance:

```html
<script
  src="https://your-chatai-instance.example/widget/chat.js"
  data-assistant-id="asst_your_public_id"
  async
></script>
```

Locally:

```html
<script
  src="http://localhost:3000/widget/chat.js"
  data-assistant-id="asst_your_public_id"
  async
></script>
```

## Self-hosted script

Serve `chat.js` from your static origin and point API calls at ChatAI:

```html
<script
  src="https://static.example.com/chat.js"
  data-assistant-id="asst_your_public_id"
  data-api-url="https://your-chatai-instance.example"
  async
></script>
```

From this monorepo:

```bash
pnpm examples:prepare-widget
# writes examples/html-widget/chat.js
```

Open [`examples/html-widget/self-host.html`](https://github.com/nightzeros/chatai/blob/main/examples/html-widget/self-host.html).

If `data-api-url` is missing or wrong, the launcher may appear while config/chat fail (CORS, 404, wrong host).

## Data attributes

| Attribute | Required | Meaning |
| --- | --- | --- |
| `data-assistant-id` | Yes | Assistant `publicId` |
| `data-api-url` | Self-host only | Absolute ChatAI API origin |
| `data-voice` | No | Set to `off` to hide the Voice button on this page even when the assistant offers Voice |
| `data-voice-experience` | No | `classic` (default), `orb`, `dock`, `guided`, `companion`, or `side-panel` — overrides the assistant Customize setting for this page |
| `data-voice-captions` | No | `on` or `off` — default visibility of the stage captions panel (ignored by Classic) |

Appearance (colors, position, suggested questions, Voice experience) is controlled from **Customize** on the assistant and loaded at runtime — keep Customize **saved** so embeds match the draft preview.

## Voice (preview)

When the assistant owner turns on **Offer Voice in the public widget** (assistant **Settings → Privacy**) and the instance has a Voice provider configured, the widget shows a microphone button next to the message box. Visitors can switch between typing and speaking in the same conversation.

- **Classic** (default): mic toggle in the composer and a waveform status strip.
- **Orb**: while Voice is active, a centered stage replaces the transcript and composer (identity → orb → status → optional captions → mute / End / Back to chat).
- **Dock**: a **Talk** control beside the chat launcher expands into a compact voice card (not the full Orb scene). Opening Talk never starts the mic; Start inside the card does. Talk and the text chat panel are mutually exclusive — opening chat ends an active Dock call.
- **Guided**: a welcome canvas with the assistant’s configured name, welcome text, and real suggested questions. Tap a question to ask by text, or Start conversation for the shared voice stage (with “Try saying…” hints while live). No fabricated product cards or booking flows.
- **Companion**: an abstract character canvas with the assistant’s configured name and welcome speech, then the shared voice stage with the character (instead of the orb) during the call. No invented persona names or commerce actions.
- **Side panel**: a tall edge sheet beside the host page (transcript + composer when idle; shared Orb stage while Voice is active). Layout only — ChatAI does not scrape the page or claim “looking at” product context.
- Choose the experience under **Customize → Voice experience**.
- Answers come from the same Purpose, instructions and Knowledge as text chat; provider keys never reach the browser.
- Voice needs HTTPS (or `localhost`), microphone permission and WebRTC. Otherwise the widget explains why and text chat keeps working.
- The Voice bar / Orb meta shows **Not saved**, **Voice transcript not saved** or **Recording** depending on the assistant's privacy settings. Recording always asks the visitor to **Agree and start** first.
- Hide Voice on a page with `data-voice="off"`.
- Voice plays only speech ChatAI has approved (the playback gate). The hosted `chat.js` supports it; the npm `@nightzeros/chatai-widget` needs 1.2.0 or later, and older versions get **Voice needs an updated chat widget**.

Setup, recordings, consent, usage minutes and troubleshooting: **[Voice (preview)](/docs/voice)**.

## Auth model

Widget chat uses `publicId` in the request body and **no API key**. REST SDK access uses Bearer `sk_` keys — see [API](/docs/api) and [SDK](/docs/sdk).
